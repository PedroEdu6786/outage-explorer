- It means **switching to the new dataset and recording that the refresh succeeded in one database transaction**—both changes happen together, or neither happens. For example, suppose users currently read snapshot **A**, and a refresh builds snapshot **B**: 1. Upload B’s Parquet files to **S3** and verify them. 2. Start a PostgreSQL transaction. 3. Register B, change the active snapshot reference from A to B, and mark the refresh as **succeeded**. 4. Commit the transaction. This prevents inconsistent states such as “refresh succeeded” while A is still active, or B becoming active without its successful refresh record. **PostgreSQL stores the reference and refresh status; the analytical data stays in S3.** The S3 uploads happen before the transaction and are not part of it. After commit, new readers select B. Readers already using A continue with A. If the transaction rolls back, A remains active. This is planned behavior, not implemented yet.
