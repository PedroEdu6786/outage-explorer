- **Technically, DuckDB can run inside Flask.** The separate worker is a deliberate choice in this project. Running user SQL in the API process would give that execution the process’s access to credentials, files, and database resources. Expensive queries could also exhaust API memory, and stopping a stuck query safely becomes harder. Moving it to another thread doesn’t separate those resources. The planned worker lets us restrict access and terminate execution without taking down the API. So, **under the accepted design, we need a separate execution process**. It can run on the same machine and remain part of the same application—no additional hosted service is required. Docker is one implementation option; the required boundary is isolation, not Docker itself.
